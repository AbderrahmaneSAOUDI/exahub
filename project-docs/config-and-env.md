| Property | Value |

### 1.3 Web Firebase Configuration

// firebase-config.js (CLIENT-SAFE — no secrets here)
const firebaseConfig = {
  apiKey: "AIzaSy..._YOUR_WEB_API_KEY",

  projectId: "exahub-firebase",

> **Note:** This configuration object is **client-safe** by design. The API key restricts access by domain/app, not by secrecy. It can be committed to version control.

## 2. Google Drive API Configuration

### 2.1 Google Cloud Platform Setup

| Step | Detail |
|---|---|
| GCP Project | Same project as Firebase: `exahub-firebase` |
| API to Enable | **Google Drive API** |
| Credentials Type | **Service Account** (for server-side operations) |

### 2.2 Service Account

| Property | Value |
|---|---|
| Account email | `drive-uploader@exahub-firebase.iam.gserviceaccount.com` |
| Key format | JSON (`service-account.json`) |
| Scopes | See below |

### 2.3 OAuth Scopes

| Scope | Used By | Purpose |
|---|---|---|
| `https://www.googleapis.com/auth/drive.file` | Upload operations | Access only files created/uploaded by the app |
| `https://www.googleapis.com/auth/drive` | Moderator operations | Full Drive access for moving files between folders |
| `https://www.googleapis.com/auth/drive.readonly` | Download operations | Read-only access for serving files to users |

### 2.4 Drive Folder IDs

```bash
# These are the Google Drive folder IDs that must be configured
GOOGLE_DRIVE_PENDING_FOLDER_ID=<folder-id-for-pending>
GOOGLE_DRIVE_APPROVED_FOLDER_ID=<folder-id-for-approved>
GOOGLE_DRIVE_REJECTED_FOLDER_ID=<folder-id-for-rejected>
```

**Setup Steps:**
1. Create `/ExaHub/Pending`, `/ExaHub/Approved`, `/ExaHub/Rejected` root folders.
2. Under each, use the same deep structure: `/{Country}/{University}/{Speciality}/{ExamType}/`.
3. Share **all three** status roots with the service account email (Editor role).
4. Copy each root folder ID from the URL (string after `/folders/`).

### 2.5 Service Account Credentials File

```json
{
  "type": "service_account",
  "project_id": "exahub-firebase",
  "private_key_id": "xxxxxx_PRIVATE_KEY_ID_xxxxxx",
  "private_key": "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n",
  "client_email": "drive-uploader@exahub-firebase.iam.gserviceaccount.com",
  "client_id": "12345678901234567890",
  "auth_uri": "https://accounts.google.com/o/oauth2/auth",
  "token_uri": "https://oauth2.googleapis.com/token",
  "auth_provider_x509_cert_url": "https://www.googleapis.com/oauth2/v1/certs",
  "client_x509_cert_url": "https://www.googleapis.com/robot/v1/metadata/x509/..."
}
```

> ⚠️ **CRITICAL:** This file contains private keys. It must:
> - **NEVER** be committed to version control
> - **NEVER** be bundled in the Flutter web build
> - **ONLY** exist on server-side environments (Cloud Functions, Cloud Run)
> - Be added to `.gitignore` immediately

## 3. Environment Variables

### 3.1 Client-Side Configuration (`.env` or `--dart-define`)

These values are **safe to include in the client build** — they are not secrets.

```bash
# === Firebase Client Config ===
FIREBASE_API_KEY=AIzaSy..._YOUR_WEB_API_KEY
FIREBASE_AUTH_DOMAIN=exahub-firebase.firebaseapp.com
FIREBASE_PROJECT_ID=exahub-firebase
FIREBASE_STORAGE_BUCKET=exahub-firebase.appspot.com
FIREBASE_MESSAGING_SENDER_ID=SENDER_ID
FIREBASE_APP_ID=1:SENDER_ID:web:APP_ID

# === App Configuration ===
APP_VERSION=1.0.0
APP_ENVIRONMENT=development  # development | staging | production

# === Server Boundary URL ===
# Points to the Cloud Function / Cloud Run endpoint that handles
# Drive operations, watermarking, and download serving
API_BASE_URL=https://us-central1-exahub-firebase.cloudfunctions.net
```

### 3.2 Server-Side Only Configuration

These values must **never** reach the client build.

```bash
# === Google Drive Service Account ===
# Path to the service-account.json file (server-side only)
GOOGLE_APPLICATION_CREDENTIALS=/path/to/service-account.json

# === Drive Folder IDs ===
GOOGLE_DRIVE_PENDING_FOLDER_ID=<folder-id>
GOOGLE_DRIVE_APPROVED_FOLDER_ID=<folder-id>
GOOGLE_DRIVE_REJECTED_FOLDER_ID=<folder-id>

# === Firebase Admin ===
# Admin SDK uses GOOGLE_APPLICATION_CREDENTIALS automatically
# No additional config needed if running on GCP infrastructure

# === Watermark Configuration ===
WATERMARK_TEXT=ExaHub
WATERMARK_OPACITY=0.15
```

### 3.3 Environment Variable Loading Strategy

| Platform | Method | Notes |
|---|---|---|
| Flutter (dev) | `flutter_dotenv` package or `--dart-define` | Loads from `.env` at build time |
| Flutter (prod) | `--dart-define` via CI/CD | Injected at build, not bundled as a file |
| Cloud Functions | GCP Secret Manager or environment config | Set via `firebase functions:config:set` or GCP console |
| Local testing | `.env` file at project root | Must be in `.gitignore` |

## 5. Required External Service Setup

### 5.1 Pre-Build Checklist

| # | Task | Status | Notes |
|---|---|---|---|
| 1 | Create GCP Console project | ⬜ | Same project for Firebase + Drive API |
| 2 | Enable Google Drive API | ⬜ | In GCP API Library |
| 3 | Create Service Account | ⬜ | Generate JSON key |
| 4 | Create Drive folders with deep structure (`/Pending|Approved|Rejected/{Country}/{University}/{Speciality}/{ExamType}`) | ⬜ | In founder's 2TB Drive |
| 5 | Share Drive folders with service account email | ⬜ | Grant Editor role on all three folders |
| 6 | Initialize Firebase project | ⬜ | `firebase init` |
| 7 | Enable Google + Email/Password auth | ⬜ | Firebase Console > Authentication |
| 8 | Register Web app in Firebase | ⬜ | Get web config object |
| 9 | Register Android app in Firebase | ⬜ | Download `google-services.json` |
| 10 | Register iOS app in Firebase | ⬜ | Download `GoogleService-Info.plist` |
| 11 | Run `flutterfire configure` | ⬜ | Generates `firebase_options.dart` |
| 12 | Deploy Firestore security rules | ⬜ | See `data-integrations.md` |
| 13 | Set up Cloud Functions (if used) | ⬜ | For server-side Drive operations |
| 14 | Create `.env` file from template | ⬜ | Fill in actual values |

### 5.2 Firebase CLI Commands

```bash
# Install Firebase CLI
npm install -g firebase-tools

# Login to Firebase
firebase login

# Initialize project
firebase init  # Select: Firestore, Functions (optional), Hosting (optional)

# Configure Flutter
dart pub global activate flutterfire_cli
flutterfire configure --project=exahub-firebase

# Deploy Firestore rules
firebase deploy --only firestore:rules

# Deploy Cloud Functions (if applicable)
firebase deploy --only functions
```

## 7. Platform-Specific Configuration Notes

### 7.1 Web

- Firebase config is loaded via `firebase_options.dart` (generated by FlutterFire CLI).
- CORS headers must be configured on any server-side endpoint that serves files to the browser.
- Service workers may be needed for offline metadata caching on web.

### 7.2 Android

- `google-services.json` must be placed in `android/app/`.
- SHA-1 and SHA-256 fingerprints must be registered in Firebase Console for auth.
- Minimum SDK version: API 21 (Android 5.0) recommended.

### 7.3 iOS

- `GoogleService-Info.plist` must be placed in `ios/Runner/`.
- Push notification entitlements must be configured for FCM.
- Minimum iOS version: 13.0 recommended.
